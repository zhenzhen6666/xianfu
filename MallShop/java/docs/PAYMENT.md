# 支付接口扩展说明

订单与支付通过 `PaymentProvider` 接口解耦。当前提供 `MockPaymentProvider`，用于本地联调，不产生真实扣款。

## 新增支付渠道

1. 新建 Spring Bean 并实现 `PaymentProvider`。
2. `channel()` 返回唯一渠道名，例如 `WECHAT`。
3. `create(...)` 调用渠道统一下单接口并返回小程序支付参数。
4. `refund(...)` 调用渠道退款接口。
5. 新增渠道独立回调 Controller，先按渠道规范验签，再调用支付状态落库逻辑。

订单创建、库存扣减、优惠券和积分抵扣不依赖具体支付渠道。支付回调以 `payment_no` 为幂等键；重复成功通知不会重复修改订单和销量。

## 生产安全要求

- 商户号、APPID、私钥、证书与 API 密钥只从密钥管理服务或环境变量读取，禁止提交到代码仓库。
- 回调必须验签，并核对商户号、订单号、金额和币种。
- 先落支付流水，再幂等推进订单状态。
- 退款金额不能超过原支付可退余额。
- 记录渠道请求号，便于对账和问题追踪。
- `MockPaymentProvider` 与开发登录必须在生产环境禁用或通过网关隔离。
